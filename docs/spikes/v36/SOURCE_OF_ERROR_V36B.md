# 问题的源头：是模型的能力上限，还是没给够上下文（2026-09-15）

> 问题：B 轮的十条假陈述与五道未出答案的题，源头到底在哪儿——LLM 做不到，还是 LLM 没被给到它需要的东西？
> 读法：对每一条缺陷问同一个可证的问题——**出错那一刻，决定性的信息在不在它的上下文里**。
> 在，就不是"没给够"；不在，就问"这份知识桌子自己有没有"。材料是 B 轮的 trace、
> `analyst_reports` 的全文、两段 system prompt 与 `for_lead` 的载荷，以及对 `answer_check` 的只读复现。

## 0. 结论

**十五条缺陷里，十四条不是模型的能力上限。**分布是：

| 源头 | 条数 | 是谁的问题 |
|---|---|---|
| 系统给了**错的或假的**上下文 | 3 | 桌子 |
| 桌子**自己有这份知识、但从不交给模型** | 4 | 桌子 |
| 系统**自己制造的歧义**（同一个值三条身份） | 1 | 桌子 |
| 信息**在上下文里**，模型已经察觉并把对的话写在了另一个字段 | 3 | 管道 |
| 信息**在上下文里**，模型没察觉，而且没有任何检查 | 3 | validation 缺一条查表 |
| 模型**真的读错了散文** | 1 | LLM |

最锋利的一条证据：**在同一轮里，模型四次察觉到了周期不符并把它写下来**——
Q04 的同一个句子里既写着 "over the last twelve quarters" 又写着 "the intervening **annual** points"；
Q12 的 caveat 写着 "came back on **quarter-end dates rather than three year-end dates**"，finding 里却写 "over the last three years"；
Q06 的两条 caveat 分别写明"利息费用是 2021/2022/2023 的年度点""税前、净利与差额是 2023/2024/2025 的年度点"。

**而主分析师的 system prompt 里一次也没有出现 `caveat` 这个词。**
域分析师被告诉的是"What you had to assume or leave out goes in caveats; **the lead states those to the reader**"；
E10 的载荷里确实带着 `caveats`；`HOW_TO_CITE` 不提它；主分析师被告知会收到的是
"a finding for each of your lines, what it could not do … and a report id"——**没有 caveats**。
**一句单向的承诺。**这一轮里唯一把真话写下来的那个字段，读者从来没有被指到过。

所以对"是不是没给够上下文"这个问题，最准确的答案是：**大多数时候给够了，甚至模型自己把对的写了出来，
只是写进了一个下游没人读的格子。**

## 2. 三类源头，各自的性质

### 2.1 桌子给了错的上下文（3 条）——模型做的完全正确

Q10 / Q18：`not_done` 带着 `said`（desk 的原话）与 `boundary`（id），提示词说"带 id 来的文字可以引"。
模型照做。那条事实记在一个 `status=rejected` 的步上，而 `ledger.load` 只读 completed。
**模型被告知一件假的事，然后因为相信它而被拒。**

Q02 的 9209.8%：digest 显示的就是这个数，模型照抄——它连"这个数不对"都无从知道，
因为 `fcf_to_debt` 的 unit_class 判错发生在事实出生的地方。

这一类**与模型无关**。给再多上下文也不会好，只会把错的传得更远。

### 2.2 桌子有这份知识、但从不交给模型（4 条）

- **Q03**：桌子知道什么叫一段可核的引文——它在 `gate._MIN_QUOTED_WORDS = 4` 里**执行**这条规则。
  它对模型说的是"quote the passage's own words"（`mark_mismatch`）和"quote the passage that states it"（`unsourced_figure`）。
  模型两条都照做了，两次都被拒。复现证明唯一走得通的写法是逐字引一段含这个数的 ≥4 词原话——
  **这句话从未出现在任何提示或拒绝信里。**
- **Q07**：桌子知道怎么跨发行人排序——`issuer_profitability` 的示例程序就叫 "margins across names, then the ordering"。
  而 `issuer_earnings_quality`（cash conversion 的域）的两个示例程序里没有 rank 也没有 vector，
  它的 `compare` 三条**全是同一家对自己的过去**："against the issuer's own prior periods""against revenue growth over the same windows""against the same days a year earlier"。
  模型做的正是这份知识教它的事——把每家跟自己的上期比。**知识不是缺席，是指了反方向。**
- **Q14 / Q15**：`factor_share = −125.5%` 是什么意思、`divide(market_value, adv)` 怎么换成"20% ADV 下的天数"，
  桌子都知道（前者是它算的，后者是问题问的），都不在域知识里。

这一类**是真正的"没给够上下文"**，而且给得起：这四份知识桌子已经有了，只是在代码里、在别的域里、在门的常量里。

### 2.3 信息在上下文里（6 条）——其中 3 条模型已经写对过

这是最大的一类，也是最值得说清的一类。

**Q09 是极端例子**：分析师写的句子是
```
The last twelve quarter readings for days sales outstanding are
21.43 [f_…@2020-09-26], 26.22 [f_…@2021-09-25], 26.09 [f_…@2022-09-24],
28.10 [f_…@2023-09-30], 31.19 [f_…@2024-09-28], and 34.89 [f_…@2025-09-27].
```
六个年度日期由它自己打出来，句子说"twelve quarter"。**上下文不可能更充分。**

**而在同一轮里它四次做对了**（§0）。所以这不是"做不到"，是"不保证做"。
更准确地说：模型被要求**核对自己刚写的两样东西是否一致**——而这恰恰是 V33 起本架构
**明确决定不依赖模型去做**的那类工作（"正确性是代码里的一次查表"）。

**这一类的三条（Q04 / Q06 / Q12）还多一层**：对的话写出来了，写进了 caveat 或同一句的后半截，
然后在传给读者的路上丢掉。Q06 尤其干净——两条 caveat 分别写明两个窗口，主分析师把两条序列并成了"同一个三年"。

**所以对这六条，"给更多上下文"是错的处方**，正确的处方是两件：
1. **把已经写对的那句话接到读者身上**（E10 的 `caveats` 进主分析师的提示词与 `HOW_TO_CITE`）；
2. **把可查的断言变成查表**：周期词对事实的 `window` 与点间距（5 条）、最高级对**是哪个排序**的位次（1 条）。
   两者都只用账本上已有的字段，不需要模型多知道任何事。

### 2.4 系统制造的歧义（1 条）

Q08：三条事实的值是**同一个浮点数** `0.22912850875324786`，身份不同，只有两条带 `place=1`。
digest 本来有"一个读数只显示一次"的机制（`tell_apart` 按 subject/measure/as_of/value 合并，重复的挂在 `also` 上），
但这三条的 **measure 不同**（`capex.divide.revenue` / `capex_intensity` / `vector(capex_intensity)`），合不了，
而且它们分属两次派单，根本不经过同一份 digest。
**模型面对三个长得一模一样、只有 id 不同的东西，挑错了一个。**这不是上下文不够，是上下文里有两个诱饵。

### 2.5 真正的模型问题（1 条）

Q19：段落写的是 "AWS sales **increased** 20% in 2025"，模型写成 "AWS **is 20% of** Amazon's revenue"，
而问题问的正是份额。增速读成份额，是一次实打实的散文误读。
值得注意的是，桌子对这一类**本来就有答案**：只在正文里出现的数字必须**引**、不许转述——
和 Q03 是同一条规则。而那条规则的出路正好是走不通的那条（§2.2）。

## 3. 按四角色收束

- **LLM**：十五条里真正属于它的是 **1 条**（Q19 的散文误读）。其余它要么做对了被系统坑（3 条），
  要么在桌子给错方向时照做（4 条），要么做了架构本来就不打算依赖它做的核对（6 条），要么在两个同值诱饵间挑错（1 条）。
- **tool**：给错上下文（T10、unit_class）、制造歧义（同量三身份）、以及**把自己执行的规则藏起来**（≥4 词引文）。
- **skill**：域知识指反方向（Q07 的 compare 全是对自己比）、两处读法缺席（factor_share、days-to-liquidate）。
- **validation**：可查而未查的断言——周期词对窗口、最高级对"哪个排序"。这两条都是集合与查表，没有判断。

## 4. 处方的顺序（由源头推出，不由现象推出）

1. **先别对模型说假话** — T10。2 题。
2. **把已经写对的那句话接到读者身上** — E10 的 `caveats` 写进主分析师提示词与 `HOW_TO_CITE`。Q06、Q12，可能连带 Q04。
3. **把可查的变成查表** — V4 周期词对 `window` 与点间距（5 条）；V1 最高级须落在**问的那个排序**上（Q11、并复查 Q08）。
4. **把桌子执行的规则告诉模型** — V5 拒绝信直接给出可照抄的 ≥4 词原话（Q03）；S3 给按发行人算的域补跨发行人排序程序（Q07）；两处读法进域知识（Q14、Q15）。
5. **消掉自己造的歧义** — T12：同一个量不要留三条身份不同的事实（Q08）。

做完这五件，剩下的残差是 Q19 一条。**那时候再谈"模型的能力上限"才有意义**——
在此之前，十五分之十四的源头都在桌子这一侧。
